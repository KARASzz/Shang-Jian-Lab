## 角度 A：基准污染的解剖 —— 从训练-测试重叠到能力幻觉

**中心判断**
当下 LLM 基准排行榜的高分，正在被训练数据污染、题目记忆、评分脚本可被越狱等机制系统性抬高；分数提升并不对应真实能力提升，"评测榜第一"在很多场景下已经是数据卫生（data hygiene）问题而非智能问题。

**结构**
1. **开篇**：用一个具体场景（某闭源模型在 GPQA / MMLU 子集断崖式下跌）的反差，引出"榜单高分 ≠ 现场可用"。
2. **第一层：污染的三种形态**：题目级污染（直接背题）、分布级污染（同类题在预训练语料中高频出现）、评分级污染（LLM-as-judge 被 prompt 注入）。
3. **第二层：抗污染机制的成本**：动态题库、私有 hold-out、人工出题、可复现评测脚本 —— 以及为什么开源榜单很难全面铺开。
4. **第三层：能力幻觉的下游代价**：企业把榜单分数当采购信号，导致 PoC 阶段高估、生产环境低产。
5. **收束**：评测可信度的恢复，不在"再做一个新榜"，而在"是否敢公布 hold-out 与污染审计"。

## 角度 B：覆盖度陷阱 —— 为什么"全能冠军"在长尾任务上一塌糊涂

**中心判断**
主流基准（MMLU、HumanEval、GPQA、MATH、BBH 等）覆盖的是"研究社区认可的能力切片"，而不是"真实生产任务的分布"；当任务落入长尾（多模态文档理解、领域推理、Agent 工具链），榜一模型与二线模型的差距会迅速消失甚至反转，所谓"全能冠军"是一种覆盖度错觉。

**结构**
1. **开篇**：用一组反直觉数字（榜一模型在某企业内部私有 eval 上的绝对分差）建立反差，但不在此承诺具体数字，留给 writer。
2. **第一层：基准覆盖度的偏差**：英文文本/考试题偏多，代码题偏 LeetCode 风格，多轮 Agent、工具使用、长上下文、领域知识（法律/医疗/金融）几乎缺位。
3. **第二层：长尾任务的可观测证据**：企业内部评测、开源社区私榜、领域基准（医学问答、法律判决预测、Excel 公式、金融研报摘要）的横切对比。
4. **第三层：评测-部署鸿沟的结构性原因**：评测是单轮、可验证、有标准答案；部署是多轮、模糊、容错率低，二者评估目标根本不同。
5. **收束**：呼吁"评测目标函数"对齐"部署目标函数"，而不是再造一个更大的多选题集。

**证据指针**
- 主流基准的覆盖度批评：``bing-0-?``、``brave-0-?`` 中关于 MMLU / HumanEval 局限的来源。
- 领域基准与长尾任务表现：``bing-1-?``、``brave-1-?`` 中关于 domain-specific benchmarks 的来源。
- 长上下文 / Agent / 工具使用评测：``brave-0-?``、``bing-0-?``。
- 评测-部署 gap 的一手报告：``brave-1-?``、``bing-1-?``。

## 角度 C：可复现性的崩塌 —— 当一个分数不再能被独立验证

**中心判断**
榜单信任危机的另一条暗线是可复现性：闭源模型不公开权重、不公开推理配置、不公开评分脚本，第三方只能在"黑箱 API + 黑箱 judge + 黑箱题库"的组合下复现一个数字；当 prompt、temperature、tokenizer、system prompt 任何一项变化，分数都会漂移；这种"不可独立验证的第一名"本身就是行业治理问题。

**结构**
1. **开篇**：以一次具体的"分数漂移事件"切入（同一模型在不同复现条件下的明显差距），呈现"榜一不稳定"。
2. **第一层：可复现性的三道缺口**：权重/配置不公开、评分脚本与 judge 模型不公开、题库版本与防泄漏机制不公开。
3. **第二层：开源 vs 闭源的可复现性梯度**：开源模型至少可被独立审计；闭源 API 模型处于"信任厂商声明"状态。
4. **第三层：评测治理的雏形**：第三方审计、leaderboard 透明化声明（模型卡、数据卡、prompt 卡）、可签名评测日志。
5. **收束**：把"评测榜第一"从营销话术拉回工程契约 —— 没有可复现性，就没有"第一"。

**证据指针**
- 闭源模型评测的可复现性问题：``bing-0-?``、``brave-0-?`` 中关于 reproducibility of closed-model evals 的来源。
- 模型卡 / 数据卡 / 评测透明化：``bing-1-?``、``brave-1-?`` 中关于 model card / data card 的来源。
- 第三方审计与 leaderboard 治理：``brave-1-?``、``bing-1-?``。
- API 模型版本漂移与分数不稳：``brave-0-?``、``bing-0-?``。
- *数据缺口提示*：若研究摘要缺乏"具体分数漂移案例"，由 writer 改写为方法论层面的讨论，避免编造数字。
